# ADR 0002：失效 cwd 必须明确失败，不得回退根目录

- 状态：Accepted
- 日期：2026-11-07
- 相关：U1 `fix(ipc): restrict filesystem service restart to init`；`docs/reviews/2026-11-07-p0-u2-review.md`

## Context

文件系统服务是普通用户进程，可被杀死并由 init 重启。进程的 cwd 是服务实例签发的目录句柄 `(cwdh, cwdgen)`：`cwdh==0` 表示根，非零句柄只对签发它的服务实例（代际 `cwdgen`）有效。

服务重启会使代际递增。旧实现在 `fs_call` 中锁外比较代际，不符即把 `m->cwd` 置 0；服务端把 0 解释为根。结果：失效 cwd 上的相对路径**静默作用于根目录**，根目录有同名文件时操作“成功”但对象错误；fork 复制 cwd 失败时子进程同样静默落到根。锁外比较还存在“检查通过后服务重启”的窗口，旧句柄可能被新服务接受。

约束：不改变正常 cwd 生命周期与文件系统语义，不修改 `ipcmsg` 布局，不引入新的锁或线程模型。

## Decision

采用“内核分类 + 锁内代际判定 + 显式 stale 标记 + 服务端兜底”：

1. `fs_call` 按操作码分类：句柄类操作不需要 cwd；路径类操作依据路径首字符区分全绝对/含相对；未知操作返回 -1。全绝对请求置 `cwd=0,gen=0`。
2. 含相对路径的请求携带 `(cwdh, cwdgen)`，由 `ipc_call` 在 `svc[id].lock` 内与 `s.gen` 比较；不符则在入队前返回 -1。路径请求的 `h` 恒为 0，服务端从不读取 `m.gen`，因此复用它不改变协议语义。
3. 进程新增 `cwdstale`：`cwdstale=1` 表示 cwd 在 fork 时无法继承或复制，其上的相对请求直接失败；合法的根必须恰为 `(cwdh==0, cwdgen==0, cwdstale==0)`，异常组合一律不可用。
4. `sys_chdir` 成功是唯一恢复点，写入新句柄/代际并清 `cwdstale`。generation 采样竞态仍属 U5 范围：极端并发下，绝对 `chdir` 成功后相对路径仍可能因记录的代际与服务实例不符而**明确失败**（不会静默落到根目录）。
5. 服务端对“非零且 `hget` 失败”的 cwd 返回 -1，防止内核遗漏导致静默落根。
6. 服务代际递增改为 `0x7fffffff → 1`，真实代际永不发行 0（0 在 `m.gen` 中表示“任意代际”）。

## Consequences

正面：

- 失效 cwd 上的相对操作明确失败（`-1`），不再可能误操作根目录。
- 绝对路径、绝对 `chdir` 恢复、根 cwd 的语义完全不变。
- fork 不再把丢失的 cwd 变成根。
- 竞态从“可能用错目录”降级为“显式失败”。
- 无 ABI/消息布局变化；无新增锁。

代价与限制：

- 内核维护操作码到“是否需要 cwd”的分类表；新增路径类操作码必须同步更新，遗漏时由 `FS_CWD_INVALID` 兜底失败（不会静默落根）。
- 服务端兜底只能识别当前实例不认识的句柄，无法识别数值相同的重用句柄；权威性来自内核锁内比较。
- `sys_chdir`/`sys_open`/`kexec` 的代际采样仍在调用前进行（U5 范畴）：极端竞态下会得到“显式失败”，而非错误目录。
- 代际回绕在第 2^31 次注册后理论上存在数值 ABA，实际不可达。

## Alternatives

- **给 `ipcmsg` 增加 `cwdgen` 字段或负 cwd 哨兵，由服务端判定**：服务端成为唯一判定者，但需修改内核与服务端共享布局，并在被所有后端共用的 `namex` 中增加无效标志；且无法消除入队竞态，仍需锁内比较。改动面更大，与最小修改目标冲突。
- **仅把锁外比较改为返回失败**：改动极小，但“检查通过后服务重启”的窗口仍在，旧句柄仍可能被新服务接受。不可接受。
- **把失效 cwd 直接设为 `-1`**：魔数会进入句柄空间，且无法区分“根”与“丢失”，也无法表达 fork 失败与重启失效的不同恢复语义。未采用。
