## 1. 竞态的真实方向

三个创建句柄的位置（`sys_open`、`sys_chdir`、`kexec`）原先都在发请求**之前**
采样 `svc_gen()`。`gen` 只在 `sys_svc_register()` 持 `s->lock` 且 `server == 0`
时递增，单调不减。设采样值 `G`、接纳时实际服务代际 `S`，则恒有 `G ≤ S`：

- `G == S`：正常。
- `G < S`：采样与接纳之间服务重启。句柄被标 `G`，但由代际 `S` 的服务创建。
  后续操作在 `ipc_call` 锁内被拒（fail-closed）→ **虚假失败**；`fs_release`
  快速路径也拒绝 → **新服务句柄泄漏**。
- `G > S` 不可能（采样先于请求且 gen 单调）。

因此本 HEAD 的残余缺陷是“虚假失败 + 句柄泄漏”，不是“旧句柄被新服务错误解释”。
U5 修复后句柄代际恒等于实际受理代际。

## 2. callgen 锁内捕获的正确性

`ipc_call` 的接纳循环在**持 `s->lock`** 时完成最终检查：

```c
if(s->server == 0 || (m->gen != 0 && m->gen != s->gen)){
  release(&s->lock);
  return -1;                 // *callgen 保持 0
}
if(!s->busy)
  break;
sleep(&s->busy, &s->lock);
```

busy 等待结束且检查通过后，在同一临界区内：

```c
serving = s->gen;
s->busy = 1;
s->client = p;
s->req = m;
...
```

释放锁后仅写回 `*callgen = serving`，**不再**采样 `svc_gen()`。正确性要点：

- `serving` 与 `server` 指针在同一把锁、同一次临界区读取，不存在“检查旧代际、
  记录新代际”或反过来的窗口。
- 请求被该代际受理后，若服务在完成前退出，`ipc_proc_exit` 置 `ret = -1`；
  调用者只在 `h > 0` 时保存句柄，因此不会把失败请求的代际写入句柄。
- 入口 `if(callgen) *callgen = 0;` 覆盖 `server == 0`、代际不符、
  `FS_CWD_INVALID`、cwd 不可用等所有未受理路径。
- 未改变 IPC 状态机、`ipcmsg` 布局、syscall ABI 与服务授权。
- `svc_gen()` 的唯一剩余调用者 `fs_release` 运行于客户端上下文，未持任何
  svc 锁；`svc_gen` 改为持 `s->lock` 短读并带 id 范围保护，无递归获取。

## 3. 测试覆盖

仅 `P0_TEST_HOOKS` 构建。布防后本进程下一次 IPC 必为目标操作；三个重启目标
均为绝对路径：

| 场景 | 断言 | 类型 |
|---|---|---|
| open | `genrace open restarted the server`（PID 变化 + `-4 == 2`） | 机制 |
| open | `genrace open handle stays usable after the restart` | 判别 |
| chdir | `genrace chdir restarted the server`（PID 变化 + `-4 == 2`） | 机制 |
| chdir | `genrace relative open survives the restart during chdir` | 判别 |
| fork | `genrace fork child inherits a valid cwd after the restart` | 判别 |
| exec | `genrace exec restarted the server`（fork 前存旧 PID，wait 后比较 + `-4 == 2`） | 机制 |
| exec | `genrace exec survives the restart during open` | 判别 |

- fork 子进程检查 `wait` 返回 PID 与退出码；exec 子进程分别检查
  `wait == 子 PID` 与退出码 0（旧内核为 42）。
- open/chdir/exec 三条机制断言统一包含 `svc_restart(-4) == 2`。
- 断言总数 80 → **87**；`run.sh` 用 `--expect-count "fsfault: " 87`
  防止断言未执行却通过。

## 5. 不可构造的危险方向

“旧句柄被新服务复用后读到另一个文件”在本代码中不可构造：采样先于请求且
gen 单调，句柄代际只可能旧于实际服务者；旧代际句柄在 `ipc_call` 锁内被拒，
不会到达服务端。该方向的安全性由静态论证与 U2 既有断言
（`stale open file is rejected`、`stale cwd rejects relative open`）保证，
未伪造运行时覆盖。

## 6. Hook 实现审查

- 布防：`svc_restart(-3)` 用 `__atomic_store_n` 记录目标 PID，状态置 1。
- 消费：仅 `SVC_FS`；按 PID `__atomic_compare_exchange_n` 一次性消费。
- 旧 PID：持 `s->lock` 读取并处理 `server == 0`；`old <= 0` 时状态置 -1，
  不执行 kill、不声称重启成功。
- 锁纪律：`kkill`、`yield` 均在锁外；`svc.lock`/`tickslock` 只做短临界区，
  不跨 `kkill`/`yield`/`sleep`，两把锁不嵌套。
- 计时：`start`/`now` 为 `uint`，与 `ticks` 类型一致。
- 清理：`ipc_proc_exit` 的 PID compare-exchange 成功时，原子写
  `genrace_state = -1`，避免残留“已布防”状态；仅影响测试状态。
- 观测：`svc_restart(-4)` 返回状态；普通构建无任何 `genrace`/`svc_hold` 符号。

## 7. 控制台稳定性

section 0 杀服务后新增 `pause(10)`。原因：SMP 控制台逐字符输出，init 的
`file system server died, restarting` 会与客户端断言行交错，拆散
`fsfault: ` 前缀。该等待只用于输出稳定性，不参与故障注入语义；重启仍由
`svc_hold` 与 genrace Hook 确定性控制。
