# P0 阶段二 U4 审查记录：svc_xfer 长度与地址边界校验

- 日期：2026-11-08
- 实际执行模型：**DeepSeek Flash（用户确认的运行环境）**
- 分支：`fix/p0-issues`；代码基线 `3b61a14`（U3）
- 范围：仅 U4；未处理 U5（generation 采样竞态）、驱动迁移、多线程服务端、IPC/VFS 重写或 SMP 框架

## 1. 缺陷与修复点

### U4-A：`n` 的 64 位截断（P2，真实缺口）

`sys_svc_xfer()` 原以 `argint(4, &n)` 读取长度。`argint` 实现为 `*ip = argraw(n)`
（`syscall.c`），把 64 位寄存器赋给 `int`，高 32 位被丢弃：

- `0x1_0000_0004` → 4，被当作合法长度执行复制；
- `0x1_0000_0000` → 0，被当作零长度；
- `-1`（`0xFFFF...FFFF`）→ -1，被 `n < 0` 拒绝。

这是 fail-open：畸形长度被静默改写为“看似合法”的值。正常调用者原型为
`int svc_xfer(int, int, uint64, void*, int)`，编译期已截断；只有服务端手写宽
`ecall` 才可达，因此不是提权或内核内存破坏，级别 **P2**。

修复：以 `argaddr(4, &n64)` 读完整 64 位，`n64 > 0x7fffffffULL` 时拒绝，
通过后才 `n = (int)n64`。

### U4-B：范围检查的加法形式（P2，防御性加固）

原检查：

```c
if(caddr < gaddr || caddr + n < caddr || caddr + n > gaddr + glen)
  return -1;
```

静态证明（`n >= 0`）：

1. `caddr + n` 溢出 → 第二项为真 → 拒绝；
2. `gaddr + glen` 溢出 → 回绕值 `< gaddr`，而 `caddr >= gaddr` 且
   `caddr+n` 未溢出，故 `caddr+n > 回绕值` → 第三项为真 → 拒绝；
3. 两者都不溢出时，条件等价于 `gaddr <= caddr && caddr+n <= gaddr+glen`。

因此当前实现对任何 `uint64` 输入都不会因回绕而越界，**无可利用性**。改为减法形式
并显式拒绝回绕 grant，使不变式局部可验证：

```c
if(glen > ~0ULL - gaddr)
  return -1;
if(caddr < gaddr)
  return -1;
off = caddr - gaddr;
if(off > glen || (uint64)n > glen - off)
  return -1;
```

`glen != 0` 由取锁内的身份检查保证；`off <= glen` 先判，`glen - off` 不会下溢。

### U4-C：服务端 `buf`（无需新增检查）

服务端缓冲区始终经 `copyin/copyout` 逐页校验：`MAXVA`、`PTE_V`、`PTE_U`、
`PTE_W`，未映射页经 `vmfault` 以 `p->sz` 为界。`buf` 每 256 字节重新校验，
不存在需要在内核重复预检的缺口；重复预检还会破坏惰性分配语义。

### U4-D：grant 与锁生命周期（无需扩大临界区）

- grant 在 `ipc_call` 的同一次持锁内写入，客户端在 `done` 之前不可中断睡眠；
- `svc_recv` 设置 `p->xfer_client`，`svc_reply` 先清 `glen` 再置 `done`，
  `ipc_proc_exit` 置 `done`、清 `xfer_client` 并唤醒客户端；
- `busy` 跨整个请求保持，禁止并发复用 grant；
- 服务重启要求旧服务退出后新服务注册，`gen` 递增拒绝旧句柄。

## 2. 负长度 `read` 假设的修正

调查阶段确认：`sys_read` 以 `argint` 取 `n`，`fileread/filewrite` 以 `(uint)n`
（32 位）作为 grant 长度。因此 `read(fd, buf, -1)` 产生的 `glen` 是
`0x00000000FFFFFFFF`，不是 `UINT64_MAX`；该调用会正常读取文件并返回字节数，
不会返回 -1，也不会构造回绕 grant。

因此测试设计删除了“负长度 read 构造 `UINT64_MAX` grant”的错误断言，
改为独立构造回绕 grant（`read(xfd, (char*)0xFFFFFFFFFFFFFFFCULL, 8)`），
并明确该轮只验证“安全失败、不 panic”，不声称能判别溢出 guard。

## 3. 调用链与可达性

```
fssrv do_read/do_write/do_stat
  → glue.c either_copyout/either_copyin 或 main.c do_stat
  → svc_xfer → ecall → syscall.c → ipc.c sys_svc_xfer
```

`sys_svc_xfer` 仅当 `s->server == myproc()` 且 `busy && !done && !has_req &&
glen != 0` 时执行；普通进程无法到达复制路径。`gkernel=1` 的 grant 只由
`exec.c` 的 `srcread()` 创建，长度 ≤ PGSIZE，不存在回绕。

## 4. 测试设计

### 4.1 布防与触发

- `dispatch` 的 `FS_MOUNT` 分支以精确匹配
  `strlen(r->s1) == 13 && strncmp(r->s1, "__xferrange__", 13) == 0`
  布防，轮次取 `mount` 的 dev 参数（`r->a0`），返回 0，不产生挂载。
- `do_read` 仅在 `r->op == FS_READ && r->pid == xfer_range_pid` 时触发；
  先清 PID 再执行探针，执行后清轮次。非 `FS_READ`、非布防 PID 不触发；
  一次布防只触发一次；下一次布防覆盖旧状态。
- 第 3 轮先校验 `r->gaddr == 0xFFFFFFFFFFFFFFFC && r->glen == 8`；
  不匹配直接返回 -1，客户端断言失败，从而证明异常 grant 确实到达服务端。
  该轮只断言 `read` 返回 0，不检查 `xg`：grant 是 `0xFFFFFFFFFFFFFFFC`，
  与客户端保护字节无关。它验证异常 grant 到达服务端后被拒绝且系统不 panic。

### 4.2 18 个探针

5 轮共 18 个探针，覆盖：

- 合法区间内前后段复制、两个方向（4 个）；
- 越界长度、越界起点、空区间边界、`caddr+n` 回绕（7 个）；
- 回绕 grant 的双方向拒绝（2 个）；
- `-1`、宽 64 位 `0x1_0000_0004`、宽 64 位全 1 长度（3 个）；
- 服务端 `buf` 超出 `p->sz`、跨页边界（2 个）。

客户端 grant 为 `char xg[10]` 的中间 8 字节，前后保护字节在第 1、2、4、5 轮
与零长度读中检查；第 3 轮 grant 为 `0xFFFFFFFFFFFFFFFC`，不检查 `xg`。
第 2 轮 `n = 9` 探针使用 9 字节的 `S9`，`n = 4` 探针使用 4 字节的 `B`，
均不存在越界读。两个 `open` 均检查返回值，失败时输出 FAIL 且不布防，
避免留下未触发的 Hook。
`buf` 跨页探针使用 `sbrk(0)-2`，依赖已证实的 `p->sz` 页对齐
（`exec.c` 的 `PGROUNDUP`、`uvmalloc`、`p->sz = sz`；fssrv 走同一
`kexec_image` 路径）。

### 4.3 宽参数反汇编核对

fault 构建中宽长度包装被内联，`main-fault.asm` 确认：

- `0x1_0000_0004`：`a0=1`、`a1=0`、`a2=g`、`a3=&W`、
  `a4=(1<<32)+4`、`a7=27`，`ecall`；
- `0xFFFFFFFFFFFFFFFF`：`li a4,-1`，其余同上；
- `sbrk(0)-2`：`li a0,0` → `jalr sbrk` → `addi a3,a0,-2`，`a1=0`、`a2=g`。

寄存器映射与内核 `arg0..arg4` 读取一致。

## 5. 判别力

| 内核版本 | 第 4 轮宽长度探针 | 客户端结果 | 断言 |
|---|---|---|---|
| 新代码 | `-1` | `read` 返回 0，缓冲 `'Z'` | PASS |
| `3b61a14`（仅回退 `ipc.c`） | 截断为 4，返回 0，写入 `WIDE` | `read` 为负，缓冲改变 | FAIL |

负向复制树仅回退 `src/kernel/ipc.c`，其余 U4 测试代码保留：
**79 OK / 1 FAIL**，唯一失败为 `xfer invalid and wide lengths rejected`。
U1/U2/U3 与其余 10 条 U4 断言全部 PASS，失败只指向 U4-A。

**只有该宽长度探针具备旧/新判别力。** 其余探针在旧内核上同样被拒绝：

- `caddr+n` 溢出由旧加法检查的 `caddr + n < caddr` 拒绝；该输入确实发生 64 位
  算术回绕，但返回 -1 **不能单独证明是在 grant 范围检查阶段拒绝**：`caddr`
  远超 `MAXVA`，即使范围检查放行，后续 `copyout` 的页表检查也会返回 -1。
  该探针只证明畸形输入被安全拒绝；
- 回绕 grant 由旧检查拒绝，且即便范围检查漏放，`copyout/copyin` 仍会因
  `va >= MAXVA` 拒绝；
- 服务端 `buf` 跨页由未改动的 `copyin` 语义拒绝。

它们是有价值的防回退/回归测试，但不是漏洞判别测试。

## 7. 残余风险

1. **部分复制语义**：`read` 返回 -1 时客户端缓冲可能已部分写入；`write`
   返回 -1 时部分数据可能已提交。属调用者可见的数据一致性，不是内核内存
   安全问题，需原子暂存/回滚，留给后续阶段。
2. **负长度 `read` 语义**：`fileread/filewrite` 把 `int n` 转为 32 位 `uint`，
   负数变成约 4G 的长度；复制仍受用户页表与 `p->sz` 限制。属 FS 系统调用
   参数校验项，不在本轮范围。
3. **grant 溢出 guard 不可运行时判别**：回绕 grant 的 `gaddr` 必然超出
   `MAXVA`，`copyin/copyout` 会独立拒绝；guard 的价值是保持局部不变式，
   需静态审查确认。
4. **服务端自身可信度**：内核只保证不越出 `buf` 所在地址空间，`buf` 的语义
   正确性依赖 fssrv。
5. **宽参数测试仅 RISC-V**：LoongArch 只做代码级静态审查，环境补齐后需重新验收。
6. **U5 尚未处理**：generation 采样竞态不在本轮。
