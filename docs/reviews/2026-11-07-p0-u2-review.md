- 分支：`fix/p0-issues`；基准 U1 提交 `e19ea78`

## 1. 缺陷与修复点

服务重启使 `svc[id].gen` 递增，进程保存的 `cwdgen` 随之过期。旧 `fs_call` 在锁外比较 `cwdgen != svc_gen(SVC_FS)`，不符即把 `m->cwd` 置 0；服务端把 `cwd==0` 解释为根。于是失效 cwd 上的相对路径**静默作用于根目录**；若根目录存在同名文件，操作成功但对象错误。

修复由四层构成：

1. `fs_call` 按操作码判断该请求是否需要 cwd：全绝对 → `cwd=0,gen=0`；含相对 → 携带 `cwdh/cwdgen`；无需 cwd（句柄类）→ 不触碰 `m.gen`；未知操作 → 直接 -1。
2. 相对请求的 `m.gen` 由 `ipc_call` 在 `svc[id].lock` 内与 `s.gen` 比较，不符则在入队前返回 -1。这是**权威判定**，消除了锁外检查与入队之间的重启竞态。
3. `cwdstale` 显式区分“根（0/0）”与“fork 时丢失的 cwd”，后者上的相对请求直接 -1。
4. 服务端对“非零且 `hget` 失败”的 cwd 返回 -1，作为纵深防御。

## 2. 对验收目标的逐条论证

| 目标 | 实现 | 证据 |
|---|---|---|
| 失效 cwd 绝不静默当根 | `fs_cwd_usable` 拒绝所有非 `(0,0,0)`/`(h>0,g>0,stale=0)` 组合；相对请求过期由锁内比较拒绝 | 定向测试 62 OK；负向树 15 FAIL |
| 失效 cwd 的相对路径明确失败 | `fs_call` 返回 -1，不发送 IPC | `stale cwd rejects relative *` 全部 OK |
| 绝对路径仍可用 | `FS_CWD_ABS` 置 `cwd=0,gen=0`，与服务实例无关 | `absolute open/read/link/mount works with stale cwd` OK |
| 绝对 chdir 后相对访问恢复 | `sys_chdir` 成功后同时写 `cwdh/cwdgen` 并清 `cwdstale` | `absolute chdir restores relative access`、`relative link works after recovery` OK |
| fork 不把丢失 cwd 变根 | `fs_dup_cwd` 在父 stale 或复制失败时只置子 `cwdstale`，不写根；父失效时携带父代际交由 `ipc_call` 拒绝 | `fork child does not inherit a root cwd`、`fork child cwd checks passed` OK |
| 正常 cwd 生命周期与 FS 语义不变 | `semantics`、`test_baseline` 全 PASS；正常构建通过 | 回归证据目录 |

## 3. 关键设计取舍

- **不改 `ipcmsg` 布局**：路径请求的 `h` 恒为 0、`gen` 恒为 0（memset），服务端从不读取 `m.gen`，因此把 `m.gen` 复用为“cwd 所属服务代际”不改变任何现有语义。新增字段方案（ADR 中的方案 B）会同时改内核与服务端共享结构，并在被所有后端共用的 `namex` 中增加无效标志，改动面更大。
- **不使用负 cwd 哨兵**：`cwd` 是服务端句柄，魔数会与句柄空间混淆；且服务端判定无法消除“检查通过后服务重启”的入队竞态，仍需锁内比较。
- **`FS_CWD_INVALID` 而非默认 REL**：未来新增路径操作码若忘记分类，会在发 IPC 前失败，而不是默认按相对路径处理；这是 fail-closed 的关键。
- **`cwdstale` 而非“把 cwd 设为 -1”**：`-1` 作为句柄会与 `hget` 的边界检查纠缠，且无法表达“根”与“丢失”的区别；独立布尔字段语义清晰，不产生 ABI。

## 4. 并发与锁序

- `fs_call` 不持锁，只读本进程字段；`ipc_call` 在 `s->lock` 内检查 `server` 与 `gen`，随后 `sleep(&s->busy, &s->lock)`。无新增锁、无新增嵌套。
- `fs_dup_cwd` 在 `np->lock` 释放后调用（既有约束），内部只调用 `ipc_call`；已删除所有无锁 `svc_gen()` 预判。
- `np` 在 `fs_dup_cwd` 返回前不会被置为 RUNNABLE，`cwdstale` 在发布前写入，无并发观察者。
- 代际递增与其对 `s->server` 的赋值同处 `sys_svc_register` 原有的 `s->lock` 区间，未扩大锁范围。

残余风险（如实记录，不属 U2 修复范围）：

1. `sys_chdir` 在调用前采样 `svc_gen`；采样与入队之间若服务重启，chdir 可能成功但记录旧代际，此后相对路径被**明确拒绝**。U2 将其从“静默错文件”变为“显式失败”，彻底修复归 U5。
2. `sys_open`/`kexec` 的同类采样竞态（B1/U5）保持不变。
3. 代际 `0x7fffffff → 1` 回绕：真实代际永不发行 0（0 表示“任意代际”），避免 `INT_MAX` 有符号溢出；第 2^31 次注册后理论上存在数值 ABA，需约 21 亿次重启，实际不可达。
4. `sys_svc_register` 在 `release` 之后 `return s->gen` 的锁外读为既有行为；`svcid` 只属于 boot 启动的单一进程，当前无可利用并发，U2 未改变。
5. 服务端兜底只能拒绝“当前实例不认识的非零句柄”，**不能**识别数值相同的重用句柄；正确性不依赖它，依赖锁内代际比较。

## 5. 实现偏差与测试修订

- 测试顺序按审核意见调整为 A（不改变 cwd 的 stale 相对操作 + 绝对正例）→ B（父仍 stale 时 fork/exec）→ C（最后做 stale 相对 `chdir`）→ D（绝对 `chdir` 恢复）。原因：旧代码下相对 `chdir` 可能成功并“治愈”父 cwd，使 fork 测试失去判别力。
- 负向树首次运行发现 `link("linkdir","/linkabs")` 因前一条相对 `unlink("linkdir")` 在旧代码中已删除源文件而失去独立性；改为以根诱饵 `/keep` 为源，该断言在负向树中恢复 FAIL。
- `mknod("devx",1,1)` 经核实：`do_mknod` 不查询 `devsw`、不校验 major/minor 范围，旧代码下确实创建 `/devx`；存在性探针使用 `unlink` 而非 `open`，因为 `sys_open` 会拒绝超出 `[0,NDEV)` 的设备号。
- 第二轮人工复核确认实际代码已是单一 `s->gen` 条件递增、`fs_call` 无 `svc_gen` 读取、`dispatch` 仅解析一次 cwd；仅加固测试 wait：5 个 fork 子进程各自只 wait 一次，保存返回 pid 与 fork pid 比对，状态变量每次重置为 `-1`，断言总数保持 62。复跑正向 PASS、负向 15 FAIL 不变。
