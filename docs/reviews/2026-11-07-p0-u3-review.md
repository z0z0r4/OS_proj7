- 日期：2026-11-07

## 1. 缺陷与修复点

`sys_svc_xfer()` 只显式判断 `dir == XFER_FROM_CLIENT`，其余所有值落入 `else` 并按 `XFER_TO_CLIENT` 执行。因此 `dir` 为 2、99、-1 等非法编码时会静默把服务端数据写入客户端 grant；`n == 0` 时循环不执行，非法方向返回 0。该校验还发生在身份与 grant 范围检查之后。

修复：在读完参数后、取锁和任何 `copyin/copyout` 之前，把方向收紧为闭集：

```c
argaddr(1, &dir);
if(dir != XFER_TO_CLIENT && dir != XFER_FROM_CLIENT)
  return -1;
```

`dir` 由 `argint` 改为 `argaddr` 读取 64 位原值，避免“低 32 位为 0/1、高位非零”的调用被截断后接受。合法调用只传编译期常量 0/1，行为不变；两个合法分支、grant 范围检查与分块复制保持原样。`n == 0` 且方向合法仍返回 0（既有行为）。

## 2. 调用链与调用点核实

```
fssrv FS_READ/FS_WRITE/FS_PREAD/FS_STAT
  → glue.c either_copyout/either_copyin 或 main.c do_stat
  → svc_xfer → usys.pl ecall stub
  → syscall.c SYS_svc_xfer → ipc.c sys_svc_xfer
```

真实调用者只有 fssrv：`either_copyout`（TO_CLIENT）、`either_copyin`（FROM_CLIENT）、`do_stat`（TO_CLIENT）。grant 来源为 `file.c` 的用户地址与 `exec.c` 的内核地址（`gkernel=1`）。U3 未改变任何调用方向或地址类型。

## 3. 身份、grant 与并发

- 仅当 `s->server == myproc()` 且 `busy && !done && !has_req && glen != 0` 时允许传输；普通进程无法到达复制路径，因此该缺陷不是提权漏洞。
- 新增判断是纯值比较，位于取锁之前，不引入新锁、不改变锁序或 IPC 状态机。
- 客户端 PID 来源已核实：`ipc_call` 在 `src/kernel/ipc.c:79` 写 `m->pid = p->pid`；`sys_svc_recv` 于 `:196/:200` 原样交给服务端。服务端一次处理一个请求，按 `r->pid` 布防可靠。

## 4. 测试设计

- 服务端 fault-only 钩子由客户端 `mount("__xferdir__", "/", 1)` 布防，使用**精确匹配**（长度 11 且内容相等），只在布防 PID 的下一个 `FS_READ` 触发，避免误伤 `FS_PREAD`（exec 内核 grant），也不接受带后缀的字符串。
- 三个探针覆盖：非法方向 `n=0`、非法方向 `n=4`、64 位非法方向 `0x100000000`（RISC-V fault-only 内联 `ecall`，不改变正常 ABI/系统调用号/`ipcmsg`）。
- 结果以位掩码编码：全部拒绝返回 -1，任一接受返回 `-1-accepted`；客户端断言 `read` 精确等于 -1 且 grant 缓冲区保持 `ZZZZ`。
- 前置合法读与后置合法读验证两个合法方向，并证明拒绝路径没有推进文件偏移或写缓冲区。
- 测试段位于 `fsfault.c` 最后，后续不再 fork；`P0_TEST_HOOKS` 未定义时服务端与客户端代码均不编译。

## 7. 残余风险

1. 64 位非法方向在 RISC-V fault 构建中有运行时验证；其他架构仅做代码级静态审查。若宽参数包装在其他架构不可用，白名单设计不受影响。
2. 白名单只能拒绝“非法编码”，不能识别“合法但方向语义错误”的服务端 bug（例如本应 FROM_CLIENT 却传 TO_CLIENT）。
3. U4 范围仍未处理：`buf`（服务端地址）不校验、`gaddr + glen` 溢出检查不完整、超大/截断 `n` 等。
4. 测试钩子仅存在于 fault 构建；普通镜像无魔法 mount 行为。
5. `n == 0` 且方向合法仍返回 0，属既有语义，U3 未改变。

## 8. 最终收尾小修订

人工复核后只收紧测试钩子，未改变内核校验逻辑：

1. **精确匹配**：`dispatch` 的魔法 mount 判断改为
   `strlen(r->s1) == 11 && strncmp(r->s1, "__xferdir__", 11) == 0`。
   `pathcall` 先 `memset` 整个消息再用 `safestrcpy` 写入并 NUL 结尾，`dispatch` 另将 `s1[MAXPATH-1]` 置 0，因此 `strlen` 不会越界；`__xferdir__` 加任意后缀不再布防。
2. **宽参数包装核对**：fault 构建反汇编确认
   `a0=1 (SVC_FS)`、`a1=1<<32`、`a2=gaddr`、`a3=&badmark`、`a4=4`、`a7=27 (SYS_svc_xfer)` 后执行 `ecall`，返回 `a0`（低 32 位符号扩展后参与位掩码）。
   寄存器变量通过 `"+r"`/`"r"` 固定到 a0..a7；`memory` clobber 覆盖系统调用的访存副作用；RISC-V 无条件码，无需 `cc` clobber；`ecall` 返回时内核恢复 trapframe，a1..a7 保持输入值，因此将 a1..a7 仅声明为输入是正确的。函数被编译器内联，符号表无独立条目，反汇编仍可完整核对。
3. **复验**：`make fault` + `make run` 为 69 OK / 0 FAIL、Result PASS；普通 `make ext2` exit 0，`P0_TEST_HOOKS`/`__xferdir__`/`svc_hold` 计数均为 0。证据见 `u3-final-fault-20261107-145712/`、`u3-final-normal-20261107-145712/`。
