# U1 审查记录：服务重启仅限 init

- 关联问题：P0-C（重启权限与并发）
- 状态：**CONFIRMED → FIXED_AND_VERIFIED**（RISC-V；LoongArch BLOCKED）
- 基础提交：`be8286b`；分支 `fix/p0-issues`

## 确认的问题

`sys_svc_restart`（`src/kernel/ipc.c`）原先只检查 `id == SVC_FS && server == 0`，不检查调用者，而该 syscall 对所有用户进程开放。任意进程可在服务停止期间调用它：
- 与 init 的合法重启并发时产生两个 boot 进程，注册失败者在 fssrv 内退出/panic；
- 检查与 `spawn_fsserver()` 之间无锁，存在 check-then-spawn 竞态。

## 修复

1. `sys_svc_restart` 增加 `p != initproc` 判定；`initproc` 以文件内 `extern` 声明引入。
2. 唯一合法调用者（init）使 check-then-spawn 天然无竞态，未引入新锁。
3. 测试专用钩子（`#ifdef P0_TEST_HOOKS`）：
   - `svc_hold` 仅用 `__atomic_store_n/__atomic_load_n`（RELEASE/ACQUIRE）访问；
   - init 在钩子生效时暂停于 `svc_restart` 内；`ticks` 每次在 `tickslock` 下读取后立即释放，**未跨 `yield()` 持锁**；
   - 等待上限 300 ticks，异常时自动恢复；
   - `KEXTRA=-DP0_TEST_HOOKS` 只由顶层 `fault` 目标传给 kernel 与 fs.img 两次构建。

## 独立审查发现与处理

| # | 发现 | 处理 |
|---|---|---|
| 1 | 新测试段重启服务后，`spid` 仍是旧值，section 1 的 `wait_new_server(spid)` 可能接受未退出的旧服务 | **已修**：section 1 在 kill 前重读 `spid = svc_pid(SVC_FS)` |
| 2 | 注释「~30 s」对 LoongArch 多 hart 不准确 | **已修**：改为「bounded; the test releases the hold much earlier」 |
| 3 | 残余 spawn→register 窗口（旧问题）：孤儿退出与 init 重启交错仍可能产生重复 spawn | **接受为残余风险**，本轮不加标志/锁（超出最小修改） |
| 4 | 导出的 `KEXTRA` 环境变量会影响所有构建；命令行 `KEXTRA` 不持久 | **接受**：受支持的目标都先 `make clean`，误用会响亮失败而非静默 |

## 边界确认

- 短路顺序保证 `svc[id]` 不会越界索引。
- `initproc` 在 `userinit` 中设置，此后不会被回收；zombie 无法发起 syscall。
- 仅 `init.c:55` 调用 `svc_restart`；正常构建返回值不变。
- `-Wall -Werror -O` 下编译通过。

## IPC / ABI 影响

无 syscall 号、`struct ipcmsg` 布局、FS_* 操作码或 fssrv 协议变化。钩子仅存在于 fault 专用构建。
