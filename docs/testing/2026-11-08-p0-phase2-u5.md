## 1. 竞态方向（按当前代码复核）

U2 文档把残余竞态描述为“旧句柄可能被标成新代际”。当前代码中三个创建句柄的
位置都在发请求**之前**采样 `svc_gen()`，且 `gen` 只在服务注册时单调递增，因此
采样值 `G` 只会**旧于**实际服务代际 `S`（`G ≤ S`），反向不可达。

真实残余缺陷：

- 采样与接纳之间发生服务重启（`G < S`）：句柄被标 `G`，但由代际 `S` 服务创建；
  后续使用在 `ipc_call` 锁内被拒（fail-closed）→ **虚假失败**；
- 新服务为该请求分配的句柄无人关闭 → **句柄泄漏**；
- 不会发生“用旧句柄读到新服务的另一个文件”。

U5 修复：`ipc_call` 在**持 `s->lock`、最终 `server/gen` 校验通过、busy 等待结束**
的同一临界区内捕获 `serving = s->gen`，与占用请求槽同时完成；释放锁后不再采样，
通过可选 `int *callgen` 回传。修复后句柄代际恒等于实际受理代际。

## 4. 确定性 Hook（仅 `P0_TEST_HOOKS`）

- 布防：`svc_restart(-3)` 记录调用者 PID，`genrace_state = 1`。
- 消费：`ipc_call` 在 `acquire(&s->lock)` **之前**调用 Hook；仅 `SVC_FS`；
  以调用者 PID 做 `__atomic_compare_exchange_n` 一次性消费。
- 动作：持 `s->lock` 读取 `old = server ? server->pid : 0`；`old <= 0` 时置
  `genrace_state = -1` 并返回（不伪造重启成功）；否则锁外 `kkill(old)`，
  然后循环：每次持 `s->lock` 短读当前 PID，释放后检查是否已换成新 PID、
  是否超时（100 ticks）、是否被 kill，`yield()` 前不持任何锁。
- 观测：`svc_restart(-4)` 返回 `genrace_state`：1 已布防、2 观察到重启、-1 Hook 失败。
- 清理：`ipc_proc_exit` 同样以 PID compare-exchange 清除未消费的布防；
  清除成功时原子写 `genrace_state = -1`。
- 计时：`start`/`now` 使用 `uint`，与 `ticks` 类型一致。
- 普通构建：所有 Hook 均在 `#ifdef P0_TEST_HOOKS` 内；普通内核无 `genrace`/`svc_hold` 符号。

## 5. 七条断言

布防后本进程的下一次 IPC 必须是目标操作；三个重启目标操作均为绝对路径：

| # | 断言 | 类型 | 负向内核预期 |
|---|---|---|---|
| 1 | `genrace open restarted the server` | 机制（含 `-4 == 2`） | OK |
| 2 | `genrace open handle stays usable after the restart` | 判别 | FAIL |
| 3 | `genrace chdir restarted the server` | 机制（含 `-4 == 2`） | OK |
| 4 | `genrace relative open survives the restart during chdir` | 判别 | FAIL |
| 5 | `genrace fork child inherits a valid cwd after the restart` | 判别 | FAIL |
| 6 | `genrace exec restarted the server` | 机制（fork 前存旧 PID，wait 后比较 + `-4 == 2`） | OK |
| 7 | `genrace exec survives the restart during open` | 判别（子进程退出码 0；旧内核 42） | FAIL |

场景 5 子进程检查 wait 返回 PID 与退出码；场景 6/7 的 exec 子进程分别检查
`wait == 子 PID` 与退出码。场景 5 之后以绝对 `chdir("/")` 恢复 cwd。

```
fsfault: genrace open handle stays usable after the restart: FAIL

fsfault: genrace fork child inherits a valid cwd after the restart: FAIL
fsfault: genrace exec survives the restart during open: FAIL
```

归属：旧内核在请求前采样，Hook 重启后请求由新代际受理，句柄仍带旧代际，
后续 read/相对 open/FS_DUP/FS_PREAD 在 `ipc_call` 锁内被拒。三条机制断言在
两种内核上都通过，证明失败可归因于采样时机而非 Hook/重启路径。

**判别力边界：** “旧句柄被新服务复用后读到另一个文件”的危险方向在当前代码中
不可构造（采样先于请求 + gen 单调）；不伪造该运行时覆盖。安全性由 §1 静态论证
与 U2 既有断言（`stale open file is rejected`、`stale cwd rejects relative open`）
共同保证。
