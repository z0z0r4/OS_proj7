## 2. 内核修改（Stage A）

```c
argaddr(4, &n64);
if(dir != XFER_TO_CLIENT && dir != XFER_FROM_CLIENT)
  return -1;
if(n64 > 0x7fffffffULL)
  return -1;
n = (int)n64;
if(id <= 0 || id >= NSVC)
  return -1;
```

```c
if(glen > ~0ULL - gaddr)
  return -1;
if(caddr < gaddr)
  return -1;
off = caddr - gaddr;
if(off > glen || (uint64)n > glen - off)
  return -1;
```

- 方向白名单位置不变，仍在长度校验之前。
- `n64 > INT_MAX` 同时拒绝高位非零与符号扩展负数；通过后才转为 `int`。
- 无溢出时减法形式与旧加法检查等价；回绕 grant 在减法前显式拒绝。
- 合法调用者（原型 `int n`）行为不变。

## 3. 测试架构

- 仅 fault 构建（`KEXTRA=-DP0_TEST_HOOKS`）；普通构建零钩子。
- 客户端 `mount("__xferrange__", "/", round)` 布防：`dispatch` 以
  `strlen(r->s1) == 13 && strncmp(r->s1, "__xferrange__", 13) == 0` 精确匹配，
  记录 `xfer_range_pid = r->pid`、`xfer_range_round = r->a0`，返回 0，不产生挂载。
- 服务端 `do_read` 在 `r->op == FS_READ && r->pid == xfer_range_pid` 时：
  先清 `xfer_range_pid`，执行对应轮次探针，再清 `xfer_range_round`，返回探针结果。
  只有下一个匹配 PID 的 `FS_READ` 会触发；不匹配的读不影响布防；一次布防只触发一次。
- 客户端断言 `read(...) == 0`：服务端任一探针不符预期则返回 `-1 - 偏差位掩码`，
  `read` 变负，断言失败并暴露偏差。
- 第 3 轮服务端先校验 `r->gaddr == 0xFFFFFFFFFFFFFFFC && r->glen == 8`；
  不匹配直接返回 -1，客户端断言失败，从而证明异常 grant 确实到达了服务端。
  该轮只断言 `read` 返回 0（服务端两项探针均被拒绝），不检查 `xg`；
  它验证“异常 grant 到达服务端后被拒绝且系统不 panic”。

### 3.1 客户端 grant 与源缓冲区

- 客户端 `char xg[10]`，`xb = xg + 1`，grant 为中间 8 字节，长度 8；
  `xg[0]`、`xg[9]` 为前后保护字节。
- 第 1 轮断言两个保护字节仍为 `'Q'`；第 2、4、5 轮与零长度读断言 10 字节全为 `'Z'`。
  第 3 轮的 grant 是 `0xFFFFFFFFFFFFFFFC`，与 `xg` 无关，只断言 `read` 返回 0。
- 服务端源缓冲区：`A[4]`、`B[4]`、`W[4]`、`S9[9]`。第 2 轮 `n = 9` 探针使用
  `S9`（"ABCDEFGHI"，9 字节），`n = 4` 的探针使用 4 字节的 `B`，均不存在越界读。

### 3.2 五轮探针（18 个）

设正常轮次 `g = r->gaddr`，grant 长度 8。

| 轮 | 探针 | 预期 |
|---|---|---|
| 1 | `TO, g, A, 4` | 0 |
| 1 | `TO, g+4, B, 2` | 0 |
| 1 | `FROM, g, got, 4`，并校验 `got == "ABCD"` | 0 |
| 1 | `TO, g+6, got, 2` | 0 |
| 2 | `TO, g, S9, 9` | -1 |
| 2 | `TO, g+5, B, 4` | -1 |
| 2 | `TO, g+8, A, 1` | -1 |
| 2 | `TO, g+8, A, 0` | 0（空区间） |
| 2 | `TO, g-1, A, 0` | -1 |
| 2 | `TO, g-1, A, 1` | -1 |
| 2 | `TO, UINT64_MAX-1, A, 4` | -1（`caddr+n` 回绕） |
| 3 | `TO, 0xFFFF...FFFC, A, 4` | -1 |
| 3 | `FROM, 0xFFFF...FFFC, got, 4` | -1 |
| 4 | `TO, g, A, -1` | -1 |
| 4 | 宽长度 `TO, g, W, 0x1_0000_0004` | -1（新内核） |
| 4 | 宽长度 `TO, g, A, 0xFFFFFFFFFFFFFFFF` | -1 |
| 5 | `TO, g, (void*)0x40000000, 4` | -1 |
| 5 | `TO, g, sbrk(0)-2, 4` | -1 |

第 1 轮客户端最终缓冲为 `"ABCDEFAB"`；第 2、4、5 轮保持 `'Z'`。

宽参数包装仅 `__riscv` 编译，直接以 a0..a7 传参并 `ecall`。fault 构建反汇编
（`u4-asm2-20261108-091002/main-fault.asm`）确认：

- `n = 0x1_0000_0004`：`a0=1`、`a1=0`、`a2=g`、`a3=&W`、`a4=(1<<32)+4`、`a7=27`，随后 `ecall`；
- `n = 0xFFFFFFFFFFFFFFFF`：`li a4,-1`（64 位全 1），其余同上；
- `sbrk(0)-2` 探针：`li a0,0` → `jalr sbrk` → `addi a3,a0,-2` → `li a4,4`，`a1=0`、`a2=g`。

### 3.3 跨页 `buf` 前提

`exec.c:163` 的 `PGROUNDUP(sz)`、`exec.c:165` 的 `uvmalloc`、`exec.c:209` 的
`p->sz = sz` 保证 `p->sz` 页对齐；fssrv 经 `proc.c:596` 的 `kexec_image` 走同一路径。
`sbrk(0)` 不改变 `p->sz`。因此 `buf = sbrk(0)-2 = p->sz-2` 位于栈最后一页内：
`copyin` 先复制 2 字节到内核 `tmp`，下一页 `vm.c:461` 以 `va >= p->sz` 拒绝，
`copyin` 返回 -1，`ipc.c` 在 `copyout` 之前返回，客户端 grant 一个字节都不会被写入。

## 5. 判别力（负向复制树）

证据：`u4-negative-20261108-091614/`（人工复核修正后的复验）。复制树中仅执行
`git show 3b61a14:src/kernel/ipc.c > src/kernel/ipc.c`，保留全部 U4 测试代码；
`git status` 仅显示 `src/fssrv/main.c`、`src/user/fsfault.c`、`tests/fault/run.sh`
（`ipc.c` 的 `git diff --stat` 为空，证明已回退）。

结果：**79 OK / 1 FAIL，Result: FAIL**。

唯一失败：

```
fsfault: xfer invalid and wide lengths rejected: FAIL
```

原因：旧内核 `argint(4, &n)` 把 `0x1_0000_0004` 截断为 4，探针被接受并写入
`WIDE`；服务端钩子返回负值，客户端 `read` 与缓冲检查同时失败。失败只指向 U4-A，
U1/U2/U3 与其余 10 条 U4 断言全部 PASS。

**判别力边界：**

- **只有第 4 轮的宽 64 位长度探针具有旧/新内核判别力。**
- 第 2 轮 `caddr+n` 溢出（探针 11）、第 3 轮回绕 grant（探针 12/13）、
  第 5 轮跨页 `buf`（探针 17/18）在旧内核 `3b61a14` 上同样被拒绝，
  是防回退/回归测试，不是漏洞判别。
- 探针 11 的输入确实发生 64 位算术回绕，但返回 -1 **不能单独证明是在 grant
  范围检查阶段拒绝**：`caddr` 远超 `MAXVA`，即使范围检查放行，后续
  `copyout` 的页表检查也会返回 -1。该探针只证明畸形输入被安全拒绝且不越界。
  回绕 grant 的 guard 同理，必要性由静态证明而非该运行时结果给出。
- 第 2 轮其余越界探针、第 4 轮 `-1` 与全 1 长度的预期在旧内核上相同。
- 第 3 轮回绕 grant 的 guard 不可运行时判别：即使去掉 `glen > ~0ULL - gaddr`，
  后续 `copyout/copyin` 仍会因 `va >= MAXVA` 拒绝；其必要性由 §5.3 的静态证明给出。

## 8. 其他检查

- Hook 生命周期：PID 来自 `r->pid`，轮次来自 `mount` 的 dev（`r->a0`）；
  `do_read` 先清 PID 再执行探针，执行后清轮次；非 `FS_READ` 或非布防 PID 不触发。
  `xfer_bad_pid`（U3）与 `xfer_range_pid`（U4）独立，互不影响。
- 源缓冲区长度：`S9` 为 9 字节，恰覆盖 `n = 9` 探针；`B` 为 4 字节，覆盖 `n = 4` 探针。
- 文件描述符有效性：两个 `open("/xferlegal")` 均检查返回值；失败时输出 FAIL
  且不再布防/读，避免留下未触发的 Hook。成功路径不增加 OK 行，断言总数仍为 80。
- 客户端保护字节：每轮断言，未被任何探针修改。
- 最终 QEMU 日志无 `panic:`、`kerneltrap`；工作区仅 4 个预期文件被修改。
